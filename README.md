# scene3d v0.6: видео → 3D-карта предметов → ИИ-агент (Windows 10, CPU)

Берёт обычное видео с телефона или камеры, находит предметы, определяет их положение в 3D и позволяет
работать с ними через ИИ-агента. Методика: ConceptGraphs-подобная объектная карта из литобзора
(разделы 1.2, 3.1–3.3).

## Что изменилось по сравнению с v0.1

| Было | Стало |
|---|---|
| Поза и глубина приходили из внешнего инструмента | Встроено: **Depth Anything 3 (small)** выдаёт позы, глубину и матрицу камеры прямо из кадров видео |
| Ожидались мировые координаты с осью Z вверх и метры | Карта автоматически поворачивается «Z вверх» (оценка по камерам + самая большая горизонтальная плоскость), масштаб приводится к правдоподобному |
| Запуск через bash и пути в стиле Linux/Mac | Скрипты `.bat`, UTF-8 везде, безопасное чтение картинок с кириллицей в пути, выбор устройства cpu/cuda |
| Только CLI и MCP | Добавлены **REST API** (контракт для будущего приложения на смартфоне), очередь задач, чат-агент на Claude, график сцены |

## Как это работает

```
видео ─▶ 24 самых резких кадра ─▶ DA3: позы + глубина ─▶ поворот «Z вверх», масштаб
   ─▶ FastSAM: маски ─▶ CLIP: признаки ─▶ проекция в 3D ─▶ слияние между кадрами
   ─▶ склейка дублей, теги, связи ─▶ граф сцены (data/<id>/graph)
   ─▶ AgentTools ─┬─▶ MCP-сервер ─▶ любой MCP-клиент
                  ├─▶ чат-агент (Claude, tool use)
                  └─▶ REST API ─▶ приложение на смартфоне (позже)
```

## Установка на Windows 10

Нужно: 64-битный Python 3.10–3.12, Git for Windows, 16 ГБ ОЗУ желательно, около 5 ГБ на диске (модели и torch).
**Положите проект в папку с латинским путём**, например `C:\scene3d`. OpenCV на Windows не открывает видео по
путям с кириллицей (картинки обработаны безопасно, видео нет). Видео тоже держите в латинском пути.

```bat
cd C:\scene3d
windows\setup.bat
windows\run_tests.bat      :: 63 теста без нейросетей
windows\run_demo.bat       :: полный прогон на синтетике, откроется plan.png
```

## Обработка своего видео

```bat
windows\process_video.bat C:\scene3d_videos\room.mp4 24
```

Результат: `data\scene1\graph\` (граф), `data\scene1\frames\` (ключевые кадры), `data\scene1\plan.png`
(вид сверху и сбоку: рамки и облака точек, подписи `#id тег`).

Как снимать: медленно обойдите предметы, держа телефон вертикально и держа предметы в кадре, 20–40 секунд,
хороший свет, без движущихся людей и без резких поворотов. Движение камерой вокруг предметов важнее
длины ролика.

После прогона консоль печатает блок `--- diagnostics ---` (и он же лежит в `process_info.json`): сколько масок
отброшено, сколько склеилось, сколько объектов осталось на каждом шаге фильтрации. Если объектов всё ещё слишком много или слишком
мало, меняйте `--min-obs` (по умолчанию 3: объект должен быть виден минимум в 3 кадрах) и `--delta-nn` (допуск склейки).

Если не хватает памяти или слишком медленно: уменьшайте число кадров (`... room.mp4 16`) и размер
(`scene3d process ... --max-side 480`). Время я не измерял, ориентируйтесь на строки прогресса в консоли.

## Камера 0,5× (сверхширокая) и угол обзора (v0.6)

Модель глубины сама угадывает фокусное расстояние камеры. На вашем видео она угадала угол обзора 56°×77° (портрет), у камеры 0,5×
он около 76°×108°, а отношение `fy/fx` вышло 1,21 вместо 1,00 (признак искажений). Это искривляет всю реконструкцию. Модели можно
сообщить настоящую камеру:

```bat
windows\process_video.bat D:\videos\1.mov 24 ultrawide      :: пресет: main (1x), ultrawide (0.5x), tele (2x)
scene3d process видео.mov --fov-long 100                       :: свой угол (градусы по ДЛИННОЙ стороне кадра)
windows\calibrate_fov.bat D:\videos\1.mov                    :: подобрать угол по самому видео (несколько прогонов модели)
```

`calibrate-fov` прогоняет модель с разными углами (и без подсказки) и для каждого считает, насколько реконструкция согласуется с
изображениями (ошибка в пикселях, меньше лучше). Пресеты приблизительные (у разных телефонов и при разной коррекции объектива угол
отличается), поэтому надёжнее подобрать значение по видео. После обработки консоль предупредит, если `fy/fx` далёк от 1.
Самая чистая проверка: снять ту же сцену на 1× и сравнить диагностику.

## Камера 0.5× (сверхширокая) и угол обзора (v0.6)

Depth Anything 3 сам угадывает фокусное расстояние камеры. На вашем видео 0,5× он угадал угол обзора 56°×77° (по короткой и длинной
стороне портретного кадра), тогда как у сверхширокой камеры он порядка 76°×108°, а `fy/fx` вышло 1,21 вместо 1,00. Модель принимает
известные параметры камеры, поэтому:

```bat
windows\process_video.bat видео.mp4 24 ultrawide        :: пресет: main (1x), ultrawide (0.5x), tele (2x)
scene3d process видео.mp4 --fov-long 100                :: угол по ДЛИННОЙ стороне кадра, градусы
windows\calibrate_fov.bat видео.mp4                     :: подобрать угол по самим кадрам (несколько прогонов модели)
```

`calibrate-fov` прогоняет модель при разных углах и сравнивает, насколько геометрия согласуется с совпадениями точек на кадрах
(ошибка в пикселях, меньше значит лучше). Пресеты приблизительные. После обработки в `process_info.json` смотрите
`model_fy_over_fx` (должно быть около 1,00) и `model_fov_long_deg`. Через API камеру можно задать при загрузке видео:
поля `camera`, `fov_long` или точные `intrinsics_json` (`{fx, fy, cx, cy, width, height}` в пикселях видео).

## Что делать с неверными и неуверенными названиями (v0.5)

Анализ реального запуска показал: уверенность названий в среднем 0,32, а FastSAM и CLIP видели предметы на кадре шириной 280 px
(разрешение карты глубины), хотя видео 540×960. Поэтому теперь:

- сегментация и распознавание работают на кадрах `--hi-side 960`, а глубина на своём разрешении (`--da3-res` меняет его);
- имя с уверенностью ниже `--min-tag-prob` (по умолчанию 0,35) **не присваивается**: предмет остаётся `unknown`, его не видно
  в списке, у агента и на подписях (`annotate --show-unknown` покажет). Слова-синонимы (cup/mug/glass, tv/monitor, ...) складываются;
- предметы, чьё 3D-облако не совпадает с их масками (`cover` < 0,5) или раздуто (в 3 раза больше масок), помечаются `unreliable`
  и скрываются, но остаются для `scene3d inspect`;
- `scene3d retag data\scene1 --compare` пересчитывает имена по сохранённым вырезкам за секунды (без глубинной модели) и сравнивает
  режимы `masked`, `context`, `both`; `--crop-mode` задаёт режим при обработке;
- качество рабочей копии видео повышено (`--compress-crf 23`), `--depth-conf-cut` задаёт долю отбрасываемой глубины.

## Сжатие видео

Видео с телефона весит 100+ МБ, а программе нужно около 24 резких кадров размером до 640 пикселей. Поэтому большой файл
(больше 50 МБ) или файл с нелатинским путём **сжимается автоматически** перед обработкой: длинная сторона до 960 пикселей,
15 кадров/с, H.264. Сжатая копия лежит в `data\scene1\source.mp4` (оригинал не трогается), по ней же рисуются подписи.

```bat
windows\compress_video.bat D:\videos\room.mov           :: вручную, получится room_small.mp4
scene3d process видео.mov --no-compress                   :: отключить автосжатие
scene3d process видео.mov --compress-side 720 --compress-fps 10   :: сильнее
```

Лучшее сжатие даёт ffmpeg (если его нет, используется запасной путь через OpenCV: файлы в несколько раз больше).
Самый простой способ получить ffmpeg: `pip install imageio-ffmpeg` в окружении проекта. ffmpeg заодно читает HEVC (iPhone)
и файлы с русскими буквами в пути.

## Проверка, почему у предмета неверное имя или место

```bat
windows\inspect.bat data\scene1 5,112,140       :: номера предметов, которые вызывают сомнения
```

Создаётся `data\scene1\inspect\ranking.csv` (самые подозрительные предметы первыми, с вердиктом) и лист-картинка на каждый
предмет: кадры, где он наблюдался, жёлтая рамка это где была его маска, голубая это куда проецируется итоговый 3D-объект.
Вердикты: `POSE/TIME or wrong merge` (3D-объект не накрывает свои маски: ошибка позы или в предмет слиты чужие части),
`MERGED` (облако намного больше масок: слиты несколько вещей), `TAG unsure` (геометрия в порядке, имя неуверенное: предмета нет
в словаре), `ok`. Номера предметов меняются при каждой новой обработке видео.

## Подписи на видео

После `process` можно получить копию видео с рамками и подписями `#id тег`:

```bat
windows\annotate_video.bat data\scene1              :: все предметы
windows\annotate_video.bat data\scene1 cup,bottle   :: только выбранные теги
scene3d annotate data\scene1 --keyframes             :: только ключевые кадры (точные позы), PNG в data\scene1\annotated
```

Положение камеры для каждого кадра определяется по самому изображению (совпадение точек с ключевыми
кадрами, PnP). Если кадр отследить не удалось (размытие, нет текстуры), поза берётся интерполяцией между
соседними. Консоль показывает, сколько кадров отслежено; `--no-track` включает быструю интерполяцию. Предметы, закрытые другими предметами, не подписываются. Если `.mp4` не открывается
в плеере, откройте его в VLC или перекодируйте: `ffmpeg -i annotated.mp4 -c:v libx264 -pix_fmt yuv420p out.mp4`.
Сцены, обработанные версиями до 0.3, нужно обработать заново: позы раньше не сохранялись.

**Поворот видео.** Видео с телефона хранит флаг поворота. Программа читает его сама и поворачивает кадры, в консоли
при обработке пишется `rotation applied N deg`. Если картинка всё же боком, задайте угол вручную:
`scene3d process видео.mov -o data\scene1 --rotate 90` (по часовой стрелке: 0, 90, 180, 270).

## Работа с агентом

**1. Чат-агент (Claude).** Нужен ключ API:

```bat
setx ANTHROPIC_API_KEY "sk-ant-..."     :: затем откройте НОВОЕ окно cmd
windows\run_chat.bat
> Где кружка? Что лежит на столе?
```

Модель по умолчанию `claude-sonnet-5-5`, меняется переменной `SCENE3D_MODEL`.
Агент сам переводит запросы на английский (теги английские), не называет метры до калибровки
и спрашивает подтверждение перед изменением карты.

**2. MCP.** Для Claude Desktop и других клиентов (`claude_desktop_config.json`, слэши в JSON удваиваются):

```json
{"mcpServers": {"scene3d": {
  "command": "C:\\scene3d\\.venv\\Scripts\\scene3d-mcp.exe",
  "env": {"SCENE3D_GRAPH": "C:\\scene3d\\data\\scene1\\graph", "SCENE3D_CLIP": "1"}}}}
```

**3. REST API** (то, к чему позже подключится телефон): `windows\run_server.bat`, документация на
http://127.0.0.1:8000/docs. Загрузка видео: `POST /api/scenes` (multipart `video`), затем опрос
`GET /api/scenes/{id}` до `status: done`, затем `/objects`, `/find`, `/chat`, `/plot.png`.

## Масштаб и вертикаль

DA3-small даёт относительную глубину. Поэтому карта выходит в условных единицах (программа приводит её к
правдоподобному размеру, медиана глубины 2,0). Чтобы получить метры, скажите агенту реальное расстояние
между двумя предметами: он вызовет `calibrate_scale`. Вертикаль определяется автоматически; в логе
записывается поворот в `process_info.json` (`tilt_deg`).

## Что проверено, а что нет

Проверено автотестами (16 штук, на синтетической сцене и синтетическом видео): ядро, чтение видео,
выбор резких кадров, выравнивание наклонённого мира, очередь задач и статусы, ошибка на битом видео,
цикл инструментов чат-агента (с поддельным клиентом), генерация схем инструментов, UTF-8 и кириллица.

**Не запускалось** (в моей среде нет интернета, Windows и этих библиотек), проверьте у себя:
- установка и вызов **Depth Anything 3** (`DepthAnything3.from_pretrained`, `.inference`, формат осей `extrinsics`,
  допущение: w2c в соглашении OpenCV). Если карта «зеркальная» или предметы разлетаются, первым делом
  проверьте это в `backends/geometry_da3.py`;
- установка DA3 на Windows без видеокарты (зависимость xformers; `setup.bat` пробует запасной путь);
- FastSAM, CLIP, словарные теги;
- REST-сервер (FastAPI), MCP-сервер, реальный вызов Anthropic API.

## Путь к смартфону и серверу

Приложение на телефоне будет только снимать и отправлять видео и показывать ответы. Вся тяжёлая работа
уже за REST API. Для переноса на сервер нужно: HTTPS и авторизация (сейчас нет), запуск `scene3d serve`
на сервере (лучше с GPU, тогда `--device cuda` и DA3-base), сжатие/докачка видео, хранилище сцен вместо
локальной папки. Менять ядро для этого не придётся.
